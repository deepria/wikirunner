# 즉석 경로 생성 계획

- 상태: 방장 확장 프로그램 생성 방식으로 전환해 테스트 준비 완료
- 작성일: 2026-07-28
- 목적: 문서 풀을 미리 제한하지 않고, 나무위키 내부 링크 구조에서 실제로 도달 가능한 랜덤 경기를 생성한다.

## 1. 제품 목표

방장이 `출발지·목적지 랜덤 생성`을 선택하면 서버가 나무위키의 랜덤 문서에서 출발지를 정하고,
그 문서의 내부 링크를 제한된 깊이만큼 탐색해 도달 가능한 목적지를 고른다.

참가자에게는 출발지와 목적지만 공개한다. 서버는 목적지까지 가는 경로가 하나 이상 있다는 사실만
보장하며, 생성 과정에서 찾은 경로는 경기 중 공개하지 않는다.

## 2. 범위와 비범위

### 포함

- 나무위키 랜덤 문서 응답을 출발지 후보로 사용
- 내부 문서 링크만 따라가는 방향 그래프 탐색
- 출발지와 다른 목적지 선택
- 난이도별 탐색 깊이 설정
- 생성 결과의 대기실 미리보기와 재추첨
- 선택된 출발지·목적지·생성 규칙을 경기 스냅샷에 고정

### 포함하지 않음

- 나무위키 전체 문서의 사전 수집 또는 전수 그래프 구축
- 최단 경로의 완전한 계산 보장
- 생성에 사용한 숨은 경로의 경기 중 공개
- 나무위키 검색·랜덤 문서 UI 차단 기능

## 3. 생성 알고리즘

### 3.1 기본 방식: 제한 깊이 랜덤 워크

처음에는 요청 수와 처리 시간을 통제하기 쉬운 랜덤 워크를 기본 생성기로 사용한다.

1. 서버 작업자가 나무위키의 랜덤 문서 응답을 요청하고, 최종 canonical 문서를 출발지로 확정한다.
2. 현재 문서의 허용된 내부 문서 링크를 추출한다.
3. 제외 규칙을 적용한 뒤 링크 하나를 무작위로 선택한다.
4. 리다이렉트가 있으면 canonical 문서로 정규화한다.
5. 선택한 문서를 다음 현재 문서로 삼아 목표 깊이에 도달할 때까지 반복한다.
6. 마지막 문서를 목적지로 확정한다.

이 방식은 선택 과정 자체가 출발지에서 목적지로 이어지는 방향 경로이므로, 적어도 하나의 실제
도달 경로를 보장한다. 같은 문서 재방문, 출발지와 목적지 동일, 제외 네임스페이스, 링크가 없는
문서는 재추첨 또는 재시도로 처리한다.

### 3.2 보강 방식: 제한 BFS 후보 선택

난이도 편차를 줄일 필요가 생기면 랜덤 워크와 함께 제한된 너비 우선 탐색(BFS)을 사용한다.

- 깊이: 기본 4~8, 방장이 난이도로 선택
- 문서당 최대 확장 링크 수: 설정값으로 제한
- 전체 문서 요청 수와 생성 시간: 상한 설정
- 목적지 후보: 목표 깊이 구간에서 발견된 문서 중 무작위 선택
- 제외: 시작 문서, 직전 방문 문서, 파일·분류 등 제외 네임스페이스, 링크가 지나치게 적은 문서

이 단계도 “정확한 최단 거리”는 보장하지 않는다. 대신 생성기가 확인한 경로 길이와 탐색 예산을
난이도 지표로 저장한다.

## 4. 난이도 모델

| 난이도 | 목표 생성 깊이 | 기본 방식 | 목적 |
| --- | --- | --- | --- |
| 쉬움 (기본값) | 3~4 | 랜덤 워크 | 빠른 테스트·짧은 경기 |
| 보통 | 5~6 | 랜덤 워크 + 제한 BFS | 기본 멀티플레이 |
| 도전 | 7~8 | 제한 BFS 우선 | 긴 탐색과 경로 발견 |

생성기가 찾은 경로가 존재한다는 것과 플레이어가 찾는 최단 경로 길이는 다를 수 있다. UI에는
`생성 깊이` 또는 `난이도`만 표시하고, 최단 거리라고 표현하지 않는다.

## 5. 서버·데이터 설계

### 5.1 생성 작업자

1단계에서는 현재 사용 중인 Supabase Edge Function이 제한 깊이 랜덤 워크를 수행한다. 생성 시간이
운영 한도를 넘거나 동시 생성량이 늘어날 때만 별도 작업자 또는 작업 큐로 분리한다. 이 작업자가
다음을 수행한다.

- 랜덤 문서 요청과 canonical URL 확인
- HTML에서 허용 링크 추출
- URL 정규화와 리다이렉트 처리
- 재시도, 시간 제한, 요청 속도 제한
- 생성 결과 반환

웹 앱은 생성 요청·결과 표시만 맡고, 확장 프로그램은 생성 결과가 고정된 뒤에만 경기를 시작한다.

### 5.2 저장 항목

기존 `games` 스냅샷에는 출발지·목적지와 `article_source = random`을 저장한다. 추가로 아래 메타데이터를
별도 비공개 생성 기록에 남긴다.

| 필드 | 용도 |
| --- | --- |
| `game_id` | 생성된 경기 연결 |
| `generator_version` | 알고리즘 변경 후 재현·분석 |
| `requested_depth` | 방장이 고른 난이도 |
| `discovered_path_length` | 생성기가 확인한 경로 길이 |
| `generation_seed` | 동일 조건 재현용 난수 시드 |
| `generated_at` | 생성 시각 |
| `source_urls` | 생성된 경로 공개용 canonical URL 목록 |

생성기가 발견한 전체 경로는 경기 중 참가자 API에 포함하지 않는다. 경기가 종료되면 방의 모든 참가자에게
출발지부터 목적지까지 생성기가 확인한 경로를 공개한다.

## 6. 사용자 흐름

1. 방장이 대기실의 경기 설정에서 `출발지·목적지 랜덤 생성`을 선택한다.
2. 난이도를 고른 뒤 `랜덤 경로 생성`을 누른다.
3. 서버가 생성 중 상태를 표시하고, 성공하면 출발지·목적지·난이도를 대기실에 반영한다.
4. 방장은 결과가 마음에 들지 않으면 경기 준비마다 최대 10회까지 재추첨할 수 있다.
5. 준비 완료와 카운트다운 시작 시점에 선택 결과가 불변 경기 스냅샷으로 고정된다.

## 7. 공정성·운영 원칙

- 출발지·목적지 선정은 참가자 브라우저가 아니라 서버 작업자가 수행한다.
- 생성기가 따라간 경로는 검증 자료일 뿐, 참가자에게 힌트로 노출하지 않는다.
- 링크 구조 변경, 접근 제한, 리다이렉트 실패가 있으면 해당 후보를 버리고 재생성한다.
- 요청 속도와 동시 작업 수에 상한을 두고, 캐시는 짧은 TTL로만 사용한다.
- 대규모 자동 수집 전에는 나무위키의 robots.txt와 이용 정책을 다시 확인한다.

## 8. 구현 단계와 완료 기준

### 1단계: 생성 기반 — 완료

- 랜덤 문서 요청·canonical 정규화·내부 링크 추출 모듈 작성
- 깊이 3~4 랜덤 워크 생성기 작성
- 실패·중복·제외 네임스페이스 재시도 규칙 작성

완료 기준: 생성된 모든 경기에 대해 서버가 확인한 출발지→목적지 경로가 하나 이상 존재한다.

### 2단계: 게임 연동 — 완료

- 랜덤 생성 API와 비공개 생성 기록 추가
- 대기실의 난이도·생성·재추첨 UI 추가, 기본 난이도는 `쉬움`으로 설정
- 경기 종료 후 모든 참가자에게 생성 경로를 공개하는 화면 추가
- `article_source = random` 스냅샷 고정 및 테스트 추가

완료 기준: 여러 참가자가 같은 랜덤 출발지·목적지로 정상 경기를 시작할 수 있다.

### 3단계: 난이도 보정 — 예정

- 문서별 확장 상한을 둔 제한 BFS 추가
- 목표 깊이 후보 선택, 시간 제한, 캐시 추가
- 생성 실패율·생성 시간·실제 완주 시간 관측

완료 기준: 보통 난이도 생성의 성공률과 응답 시간이 운영 기준을 만족하고, 재추첨이 과도하게 발생하지 않는다.

### 4단계: 점진적 그래프 캐시 — 예정

- 생성 과정에서 이미 확인한 문서·링크만 TTL 캐시
- 인기 문서의 재요청 감소와 실패 원인 분석
- 필요할 때만 별도 그래프 저장소 도입 검토

완료 기준: 전수 수집 없이도 반복 생성의 속도와 품질이 안정적으로 유지된다.

## 9. 주요 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 링크 수가 많은 문서에서 탐색 폭발 | 깊이·문서당 링크 수·전체 요청 수 상한 |
| 리다이렉트·삭제·ACL 문서 | canonical 확인 후 제외하고 재시도 |
| 생성 경로가 실제로는 너무 쉬움 | 난이도는 최단 거리가 아닌 생성 깊이로 표기, 이후 BFS 보정 |
| 외부 사이트 부하·정책 변경 | 요청 속도 제한, 짧은 캐시, 정책 재검토 |
| 생성 실패 또는 시간 초과 | 사용자에게 재시도 안내, 기존 수동 설정으로 즉시 복귀 |

## 10. 확정된 초기 운영값

1. 난이도 기본값: `쉬움`(생성 깊이 3~4)
2. 생성된 경로: 경기 종료 후 모든 참가자에게 공개
3. 재추첨: 경기 준비마다 최대 10회
4. 외부 문서 요청 작업자 인프라: 1단계는 Supabase Edge Function, 필요 시 별도 작업자로 분리

## 11. 구현 메모

- `GET https://namu.wiki/random`의 최종 문서를 출발지로 사용한다.
- 난이도별(쉬움 3~4, 보통 5~6, 어려움 7~8) 제한 깊이 랜덤 워크를 최대 8회 재시도한다.
- 파일·분류처럼 `:`가 포함된 네임스페이스와 순환 경로는 제외한다.
- 방의 재추첨 횟수와 경로를 저장하고, `games` 생성 시 해당 경로를 스냅샷으로 복사한다.
- 생성 경로는 `finished` 또는 `cancelled` 상태가 된 뒤에만 방 스냅샷 API로 전달한다.
- 2026-07-28 확인: Supabase Edge Function에서 `https://namu.wiki/random` 요청이 HTTP 403으로 차단된다.
  따라서 방장과 연결된 Chrome 확장 프로그램이 사용자 브라우저 네트워크에서 경로를 만들고, 서버는 방장
  확장 프로그램이 제출한 결과를 저장하는 방식으로 전환했다. 방장은 생성 경로를 알 수 있으므로 공개 경기의
  공정성을 강화하려면 추후 허용된 서버 접근 경로로 다시 전환해야 한다.
