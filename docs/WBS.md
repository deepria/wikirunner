# WikiRunner MVP WBS

- 문서 버전: v1.0
- 기준일: 2026-07-27
- 계획 기간: 2026-07-27 ~ 2026-08-21, 4주 / 20영업일
- 대상 범위: P0 MVP
- 기준 문서: [기획서](./기획서.md), [아키텍처](./아키텍처.md)
- 초기 상태: 전체 미착수

## 1. 계획 전제

### 1.1 인력 전제

| 역할 | 주요 책임 |
| --- | --- |
| PM/Tech Lead | 범위·일정 관리, ADR, 공통 계약, 기술 의사결정, 릴리스 승인 |
| Backend | Supabase Auth, PostgreSQL, RLS, Edge Functions, Realtime |
| Web | Next.js 웹 앱의 홈·대기실·경기 현황·결과 화면 |
| Extension | Manifest V3 확장, 오버레이, 탐색 이벤트 수집·복구 |
| QA/DevOps | 테스트 자동화, 관측성, 배포, 플레이테스트 운영 |

- 전체 계획은 67개 작업, 약 131 MD이며 4주 완료에는 평균 약 6.6 FTE가 필요하다.
- 최소 권장 구성은 PM/Tech Lead 1명, Backend 2명, Web 1명, Extension 1명, QA 1명, DevOps 0.5~1명이다.
- Backend, Web, Extension 담당이 병렬로 개발하고 PM/Tech Lead와 QA/DevOps가 공통 작업을 지원하는 구성을 전제로 한다.
- `1 MD`는 1명이 1영업일 동안 수행하는 작업량이다.
- 일정의 시작일과 종료일은 선행 작업 및 병렬 수행을 반영한 기준선이며, 실제 담당자 수가 줄면 재산정한다.

### 1.2 확정된 MVP 결정

| 항목 | 적용 결정 |
| --- | --- |
| 문서 선택 | 방장 직접 선택과 운영 문서 풀 랜덤을 모두 지원 |
| 뒤로가기 | 경로에는 기록하고 이동 횟수에는 포함하지 않음 |
| 위반 처리 | 경고를 생성하고 방장이 결과 확정 시 판정 |
| 사용자 인증 | Supabase 익명 인증 |
| 웹-확장 연결 | 5분 만료 일회용 페어링 코드 |
| 공식 완주 기록 | 서버가 완주 이벤트를 받은 시각 기준 |

### 1.3 범위 제외

- P1 기능: 개인 전적, 로그인 계정, 일일 챌린지, 관전자 모드, 공개 방, 경로 공유 링크
- 나무위키 전체 크롤링 및 최단 경로 계산
- 현금·상품 대회를 위한 완전한 부정행위 방지
- 모바일 브라우저 지원

## 6. 완료 정의

### 작업 완료

- 코드·migration·설정이 공통 저장소에 반영되고 리뷰를 통과한다.
- 관련 단위·통합·E2E 테스트가 통과한다.
- API·DTO·이벤트 변경에는 schema version과 호환성 검토가 있다.
- 실패·빈 상태·재시도 경로가 구현되어 있다.
- 로그에 JWT, 페어링 코드, 검색어, 전체 URL 등 민감 데이터가 남지 않는다.

### MVP 출시 완료

- 4명이 같은 방에 입장해 10초 이내에 같은 `scheduledAt` 기준으로 시작한다.
- 정상 내부 링크 이동의 95% 이상이 경로에 기록된다.
- 목표 도착 후 2초 이내에 임시 순위가 표시된다.
- 웹 새로고침, 확장 worker 재시작, 일시적 네트워크 단절 후 경기가 복구된다.
- 첫 플레이테스트 참가자 과반이 별도 설명 없이 규칙과 목표를 이해한다.
- 치명·높음 등급 미해결 결함이 없다.

## 8. 변경 관리

- P0 추가 요구사항은 일정·인력·핵심 경로 영향을 평가한 뒤 기준선에 반영한다.
- P1 요구사항은 MVP 출시 전 작업에 끼워 넣지 않고 별도 backlog로 관리한다.
- 외부 계약인 나무위키 DOM·URL 정책 변경은 일반 기능 변경보다 우선해 영향도를 평가한다.
- 각 마일스톤 종료 시 일정 편차, 미해결 위험, 다음 주 핵심 경로를 갱신한다.
