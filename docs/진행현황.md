# WikiRunner 구현 현황 및 QA

최종 갱신: 2026-08-14 (Asia/Seoul)

이 문서는 저장소 소스를 기준으로 한 구현 현황과 출시 전 QA를 관리한다. 실행·배포 방법은
[README](../README.md), 제품 범위와 규칙은 [제품 명세](기획서.md), 기술 구조는
[아키텍처](아키텍처.md)를 따른다.

## 소스 기준 현재 상태

P0 MVP의 전체 흐름은 소스에 구현되어 있다. 원격 Supabase 반영 여부, Chrome 실기기 동작,
스토어 심사는 이 저장소만으로 확인할 수 없으므로 아래 QA와 배포 점검이 필요하다.

| 영역 | 소스 상태 | 구현 내용 |
| --- | --- | --- |
| 인증·방 | 구현 | 익명 로그인, 6자리 초대 코드, 2~12명 정원, 스냅샷 조회 |
| 설정·준비 | 구현 | 직접 문서 설정, 랜덤 경로, 준비, 서버 기준 10초 카운트다운 |
| 확장 연결 | 구현·Chrome QA 필요 | 웹 버튼 기반 1분 nonce 자동 페어링, 5분 수동 코드 예비 연결, 연결 해제·재연결, 전용 경기 탭 |
| 이동·결과 | 구현 | 일반·SPA 탐색 감지, sequence·문서 연결·hash 검증, 서버 수신 시각, 경로 조회 |
| 경기 수명주기 | 구현 | 포기, 방장 종료, 다음 경기 준비, 대기 중 방 나가기·방장 강퇴 |
| 랭킹 | 구현 | 시간순·횟수순을 대기 중 설정하고 게임에 고정, 완주자만 순위 부여 |
| 복구 | 구현 | 확장 outbox·backoff, 확장 Realtime 알림 후 스냅샷 재조회, 웹 3초 polling |
| 공정 플레이 | 구현·실기기 QA 필요 | 검색·랜덤 URL 차단, 헤더/사이드바 숨김, 본문 밖·분류 링크 차단, 직접 이동·새 탭 경고 |
| 배포 산출물 | 구현 | 확장 빌드 결과는 `apps/extension/dist`, 스토어 ZIP은 `apps/extension/wikirunner-extension.zip` |

### 최근 개선

- 검색·랜덤·분류·본문 밖 링크와 브라우저 찾기 단축키는 차단·안내만 하고 서버 경고를 남기지 않는다.
- 랜덤 경로 추첨 UI는 스냅샷상 방장이고 방이 대기 상태일 때만 확장 팝업에 보인다.
- 경기 오버레이는 접기 외에 완전히 숨길 수 있으며, 확장 팝업에서 다시 표시할 수 있다.
- 확장이 알고 있는 방 탭은 경기 탭을 연 뒤 닫고, 완주·포기 확정 뒤 경기 탭을 닫아 방 화면을 연다.
  오버레이에서도 포기와 방 이동을 제공한다.
- 자동 페어링의 nonce 발급·교환과 웹 Content Script 브리지는 구현했다. 등록된 웹 도메인
  (`localhost:3000`, `wikirunner-web.vercel.app`)에서 실제 Chrome 연결·방 나가기·탭 닫기·다른 방
  진입 자동 해제 회귀가 남아 있다.
- 자동 페어링 API를 포함한 `game-api` Edge Function은 2026-08-14에 원격 Supabase 프로젝트로
  배포했으며, 현재 버전 16이 활성 상태다.

## 출시 전 필수 QA

### 자동 확인

변경 후 아래를 실행한다. 이 문서에서는 과거 실행 결과를 보증하지 않는다.

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build
pnpm --filter @wikirunner/extension package
```

### 실제 Chrome 회귀

최신 빌드의 `apps/extension/dist`를 `chrome://extensions`에서 다시 로드한 뒤 최소 두 개의
Chrome 프로필로 확인한다.

1. 방 생성·참가, 8자리 페어링 코드 교환, 준비와 동시 카운트다운을 확인한다.
2. 전용 탭과 오버레이가 열리고, 일반 본문 링크 이동·SPA 이동·뒤로/앞으로·새로고침이
   규칙에 맞게 기록되는지 확인한다.
3. 목표 도착 뒤 완주 시간, 이동 수, 랭킹 기준별 순위와 참가자별 경로가 일치하는지 확인한다.
4. 포기, 방장 종료, 다음 경기 준비 뒤 웹·확장 프로그램이 대기 상태로 복구되는지 확인한다.
5. 대기 상태에서 일반 참가자 나가기, 방장 강퇴, 정원 재입장과 방장·경기 중 퇴장 거부를 확인한다.
6. 방장 확장 프로그램에서 쉬움·보통·어려움 랜덤 경로를 생성하고, 준비당 10회 상한과
   종료 후 경로 공개·다음 경기에서의 카운터 초기화를 확인한다.
7. 경기 탭에서 검색·랜덤 문서·분류·헤더/사이드바 링크를 시도해 차단 안내만 표시되는지
   확인한다. 별도 나무위키 탭 이동은 `new_tab` 경고로 확인한다.
8. 데스크톱·좁은 화면·다크 테마에서 시작/목표, 준비 상태, 리더보드와 키보드 탐색을 점검한다.

문제가 생기면 재현 단계, 화면 오류 문구, 브라우저/확장 버전만 기록한다. 비밀키, JWT,
페어링 코드, 브라우저 저장 데이터는 공유하지 않는다.

## 알려진 한계와 후속 작업

- Edge Function의 나무위키 요청은 HTTP 403을 받을 수 있어, 기본 랜덤 경로 생성은 방장
  확장 프로그램의 브라우저 요청을 사용한다. 서버는 중간 링크를 독립 재검증하지 않는다.
- 공정 플레이 차단은 주소창, 개발자 도구, 다른 프로필, 확장 프로그램 비활성화와 Chrome이
  먼저 처리하는 단축키를 완전히 막지 못한다. 경고는 자동 실격이 아닌 검토 자료다.
- `new_tab` 경고는 경기 외 나무위키 탭의 이동도 포착할 수 있어, 실제 경기에서 오탐을 점검해야 한다.
- 웹은 Realtime을 구독하지 않고 3초마다 스냅샷을 조회한다.
- 공개 전에는 익명 로그인 남용 방지, Supabase Auth URL 설정, 개인정보·권한 고지, 데이터
  보존/삭제 정책, 모니터링 및 CI·배포 절차를 확정한다.
- 방장 경고 검토·실격 판정 기능은 착수했다. 기존 `violations`, `result_decisions`, run 상태를
  검토했고, 판정 이력·실격·재순위 계산을 위한 DB 마이그레이션을 추가했다. 다음 구현은
  경고 조회와 방장 UI·리더보드 반영이다. 방장 판정 API(`POST /v1/games/:id/violations/:violationId/decision`)와
  리더보드 검토 UI를 추가했고, 관련 DB 마이그레이션과 Edge Function을 2026-08-14 원격 Supabase에 반영했다.
- 이후 후보는 실제 결과 기반 난이도 보정이다.
