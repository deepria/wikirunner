# WikiRunner 구현 진행 현황

최종 갱신: 2026-07-28 (Asia/Seoul)

이 문서는 구현 완료 여부와 다음 확인 작업만 관리한다. 실행·배포 방법은
[README](../README.md), 제품 범위와 규칙은 [제품 명세](기획서.md)를 따른다.

## 현재 상태

P0 MVP의 핵심 흐름은 구현되어 원격 Supabase 환경에 반영됐다. 방 생성부터 확장 프로그램
페어링, 게임 시작, 나무위키 이동 기록, 순위, 포기·방장 종료와 다음 경기 준비까지 동작한다.

운영 공개 전 단계다. 최신 확장 프로그램을 실제 Chrome에서 여러 참가자로 점검하고
인증 남용 방지와 배포·개인정보 항목을 마무리해야 한다.

## 반영·자동 검증

- 저장소에는 스키마 마이그레이션 11건과 최신 `game-api` 구현이 있다.
- 원격 환경에서 익명 로그인과 방 생성 → 설정 → 페어링 → 준비 → 카운트다운 → 이동 →
  목표 도착 흐름을 확인했다.
- 단독 참가자의 경기 포기와 방장 확장 identity의 랜덤 경로 저장 권한을 원격에서 확인했다.
- 단위 테스트, lint, typecheck, 웹·확장 프로그램 build를 통과한 상태다.

검증 횟수나 확장 버전은 이 문서에 반복 기록하지 않는다. 최신 버전은
`apps/extension/public/manifest.json`, 최신 마이그레이션은 `supabase/migrations`를 기준으로
확인한다.

## 다음 수동 점검

최신 소스로 확장 프로그램을 빌드하고 Chrome의 `chrome://extensions`에서
`apps/extension/dist`를 다시 로드한 뒤 진행한다. 테스트 값은 고정하지 말고 실제로 본문 링크가
연결되는 시작·목표 문서를 사용한다.

### 단일 참가자

1. 웹에서 방을 만들고 확장 프로그램을 페어링한다.
2. 문서를 직접 설정하고 준비한 뒤 카운트다운을 시작한다.
3. 전용 탭과 오버레이가 나타나고 이동할 때 팝업·웹의 이동 수가 함께 갱신되는지 확인한다.
4. 목표에 도착한 뒤 완주·순위·경로가 표시되고 확장이 대기 상태로 돌아오는지 확인한다.
5. 새 경기를 시작해 팝업의 **이번 경기 포기** 후 웹과 확장이 정상 복구되는지 확인한다.

### 랜덤 경로

1. 방장 확장 팝업에서 쉬움·보통·어려움 중 하나로 경로를 추첨한다.
2. 웹 대기실의 시작·목표가 갱신되고 추첨 횟수가 증가하는지 확인한다.
3. 해당 설정으로 경기를 마친 뒤 생성에 사용한 경로가 결과에 공개되는지 확인한다.
4. 다음 경기 준비 후 추첨 횟수가 초기화되는지 확인한다.

### 공정 플레이와 다중 참가자

1. 최소 두 Chrome 프로필에서 같은 방에 참가·페어링·준비하고 같은 시각에 시작하는지 확인한다.
2. 경기 탭에서 상단 헤더, 검색·랜덤 문서와 실시간/최근 변경 영역이 숨겨지는지 확인한다.
3. 검색 클릭·단축키 차단 뒤 `search_attempt` 경고가 웹에 반영되는지 확인한다.
4. 별도 나무위키 탭 이동 뒤 `new_tab` 경고가 반영되는지 확인한다.
5. 참가자별 이동 수와 완주 순위가 서로 일관되게 보이는지 확인한다.

문제가 생기면 단계, 화면의 오류 문구, 브라우저·확장 버전만 기록한다. 비밀키, JWT, 페어링
코드와 브라우저 저장 데이터는 공유하지 않는다.

## 남은 작업

### MVP 마무리

- 위 수동 시나리오의 실제 Chrome 회귀 점검
- `new_tab` 규칙의 오탐 민감도와 나무위키 DOM 선택자 조정
- README의 배포 후 점검 절차로 최종 smoke test

### 공개 배포 전

- CAPTCHA 또는 Turnstile 등 익명 로그인 남용 방지 적용
- 운영 도메인의 Supabase Site URL·Redirect URL 설정
- 개발 중 생성한 익명 사용자와 테스트 방 데이터 정리
- CI와 배포 절차, Chrome Web Store 패키지·권한·개인정보 안내 준비
- 데이터 보존·삭제 정책과 기본 운영 모니터링 확정

### 후속 기능

- 방장의 경고 검토·실격 판정 UI와 `result_decisions` 연동
- 랜덤 경로 생성 성공률·시간·실제 완주 결과에 따른 난이도 보정
- 웹의 주기 조회를 Realtime 알림 기반 갱신으로 개선

## 알려진 한계

- Supabase Edge Function의 나무위키 요청은 HTTP 403을 받아 랜덤 경로를 방장 확장에서 만든다.
  방장은 생성 경로를 알 수 있으며 서버가 중간 링크를 독립적으로 재검증하지 않는다.
- 공정 플레이 UI는 주소창, 개발자 도구, 다른 브라우저 프로필과 확장 비활성화를 막지 못한다.
- `new_tab` 경고는 다른 나무위키 탭의 일반 이동도 포착할 수 있다.
- 웹 대기실은 현재 3초 주기로 서버 스냅샷을 조회한다.

## 갱신 기준

기능 구현, 원격 반영, 수동 확인 결과 또는 공개 준비 상태가 바뀌면 이 문서만 갱신한다.
완료된 세부 개발 일정이나 작업 분해표는 다시 추가하지 않는다.
