4. 경기시작 후 나무위키 페이지 띄움 -> 방이 열려있는 탭 종료 -> 완주 or 포기 후 나무위키 탭 종료 및 방으로 이동

5. 경로 추첨기능은 방장만 확장에 노출되도록 개선

## 1. 플로팅 오버레이 숨기기·다시 표시

### 목표

경기 중 우측 상단 오버레이에 현재의 접기와 별도로 **완전히 숨기기**를 제공한다. 숨긴 뒤에도
키보드나 팝업에서 다시 표시할 방법이 있어야 하며, 완주·전송 오류 같은 중요한 상태는 사라져도
잃지 않는다.

### 구현 단계

1. Content Script의 오버레이 상태를 `expanded`, `collapsed`, `hidden`으로 분리한다. 기존 접기
   동작은 `collapsed`로 유지한다. `hidden` 상태는 Content Script가 아닌 Service Worker가
   `chrome.storage.session`에 보관한다.
2. `hidden`일 때는 화면 요소를 `display: none`으로 전환하고, 페이지 안에는 재표시 트리거를
   남기지 않는다. 재표시는 확장 팝업의 **경기 오버레이 다시 표시** 버튼으로 제공한다.
3. 상태는 게임 탭별 `chrome.storage.session`에 저장한다. 페이지 이동·SPA 전환 때는 유지하고,
   경기 종료·포기·탭 종료 때는 삭제한다.
4. Service Worker가 현재 게임 탭에 `SHOW_OVERLAY` 메시지를 보내고, Content Script는 DOM이
   다시 그려진 경우에도 같은 상태를 재적용한다.

### 완료 기준

- 숨김 후 문서 이동, 새로고침, SPA 이동에서도 오버레이가 다시 나타나지 않는다.
- 팝업에서 즉시 다시 표시할 수 있다.
- 완주·포기 뒤 다음 경기에 이전 표시 상태가 남지 않는다.
- 오버레이가 숨겨져도 공정 플레이 차단, 이동 기록, 오류 재전송은 계속 동작한다.

## 2. 브라우저 찾기 단축키는 차단·안내만 수행

### 목표

`Ctrl/⌘+F`를 포함해 확장이 차단한 검색·랜덤·분류·본문 밖 링크 조작은 안내만 표시한다.
차단된 조작은 실제 탐색이 아니므로 서버 경고로 저장하지 않는다. 직접 이동과 별도 탭 탐색처럼
실제 탐색이 발생한 경우만 기존 검증·경고 정책을 적용한다.

### 구현 단계

1. 차단된 클릭, 검색 폼 제출, `/`, `Ctrl/⌘+K`, `Ctrl/⌘+F`를 모두 `preventDefault`와 화면 안내로
   처리하고 `FAIR_PLAY_BLOCKED` 메시지를 보내지 않는다.
2. URL 직접 입력·새 탭 등 실제 탐색은 기존 탐색 검증 및 `new_tab` 경고를 유지한다.
3. Chrome이 단축키를 먼저 처리해 Content Script에 이벤트가 도달하지 않는 경우에는 차단·기록을
   약속하지 않는다는 기존 한계를 문서에 유지한다.

### 완료 기준

- 차단된 클릭·단축키·검색 폼 제출로 리더보드의 경고 상태와 `violations` 레코드가 바뀌지 않는다.
- 직접 이동·별도 나무위키 탭 탐색은 기존처럼 경고로 남는다.
- Windows와 macOS Chrome에서 단축키 전달 여부를 각각 수동 확인한다.

## 3. 웹-확장 자동 페어링과 자동 해제

### 목표

수동 8자리 페어링 코드 입력을 없애고, 웹의 명시적 **확장 프로그램 연결** 클릭으로 같은
브라우저 프로필의 확장을 연결한다. 자동 연결은 방 나가기, 다른 방 진입, 등록된 방 탭 닫기에서
안전하게 해제한다.

### 보안·상태 설계

- 페어링 코드를 URL, DOM, 로그에 넣지 않는다. 서버가 1회용·짧은 만료(예: 60초)·소비 즉시 폐기
  nonce를 발급하고 해시만 저장한다.
- 웹 Content Script는 사용자의 클릭 뒤 nonce만 Service Worker에 전달한다. Service Worker는
  자신의 익명 세션으로 nonce를 교환한다.
- nonce는 웹 사용자, 플레이어, 방, 확장 설치를 묶어 1회만 사용할 수 있게 한다. 다른 방·다른
  사용자·만료 nonce의 교환은 서버에서 거부한다.
- 해제는 서버의 extension identity 폐기와 확장 로컬 상태 삭제를 함께 성공시켜야 한다. 한쪽이
  실패하면 다음 스냅샷 동기화에서 재시도한다.

### 구현 단계

1. DB에 자동 페어링 nonce 테이블/함수와 만료·소비·멱등성·rate limit을 추가한다. 기존 수동
   페어링과 병행한 뒤 안정화 이후 제거한다.
2. `game-api`에 nonce 발급·교환·명시적 해제 API를 추가하고 contracts의 스키마 버전을 갱신한다.
3. 웹 방 화면의 코드 발급 UI를 **확장 프로그램 연결** 버튼과 연결 상태/재시도 UI로 바꾼다.
4. WikiRunner 웹 도메인에만 주입되는 Content Script와 메시지 검증을 추가한다. 개발·운영 도메인은
   매니페스트의 고정 host permission으로 관리하며, 임의 URL 권한은 요청하지 않는다.
5. Service Worker가 연결에 성공하면 `activeRoomId`와 등록한 `roomTabId`를 저장한다. 다른 방의
   연결 요청이 오면 이전 연결을 서버에서 해제한 뒤 새 연결을 진행한다.
6. 웹 Content Script가 방 나가기·새 방 진입을 알려주고, Service Worker는 해제 API 호출과 로컬
   상태 정리를 수행한다. `tabs.onRemoved`는 등록된 방 탭의 닫힘도 처리한다.
7. 탭 강제 종료·네트워크 단절에 대비해 다음 스냅샷/확장 시작 시 서버 identity와 로컬 방 상태를
   대조해 고아 연결을 정리한다.

### 완료 기준

- 지원 브라우저 프로필에서 클릭 한 번으로 연결되며 수동 코드를 입력하지 않는다.
- 방 나가기, 다른 방 연결, 방 탭 닫기, 확장 재시작 뒤 서버와 로컬의 연결 상태가 일치한다.
- nonce 재사용·만료·다른 사용자/방의 교환이 모두 거부된다.
- 수동 페어링 제거 전과 후의 연결·해제·재연결·다중 프로필 회귀 시나리오를 통과한다.

## 4. 경기 탭과 방 탭의 수명주기

### 목표

카운트다운 뒤 전용 나무위키 경기 탭을 열면 방 탭을 닫고, 완주 또는 포기 뒤에는 경기 탭을 닫은
다음 방 화면으로 돌아간다. 플로팅 오버레이에도 **포기**와 **방으로 이동**을 제공한다.

### 구현 단계

1. 자동 페어링과 별개로, 수동 페어링을 완료할 때의 현재 탭과 팝업에서 방을 열 때의 탭 ID를
   확장에 등록한다.
2. Service Worker가 경기 탭을 성공적으로 생성한 뒤 등록된 방 탭을 닫는다. 탭을 찾지 못하거나
   닫기에 실패해도 경기는 계속 진행한다.
3. Content Script 오버레이에 `ABANDON_GAME`, `OPEN_ROOM` 메시지를 추가한다. 포기는 기존
   `abandon` API를 호출하고, 방으로 이동은 활성 방 ID의 웹 URL을 새 탭으로 연다.
4. 서버가 완주/포기를 확정하거나 팝업·오버레이에서 명시적으로 방으로 이동하면, Service Worker가
   경기 탭을 닫고 방 URL을 연다. 전송 대기 중에는 경기 탭을 닫지 않고 완료/실패 상태를 보여 준다.
5. 사용자가 직접 경기 탭을 닫으면 미전송 outbox를 보존하고, 실행 중 run은 자동 포기하지 않는다.
   다음 팝업 열기에서 포기 또는 방 복귀를 선택하게 한다.

### 완료 기준

- 시작 직후 방 탭은 경기 탭이 준비된 경우에만 닫힌다.
- 완주·포기 후 경기 탭이 닫히고 올바른 방 화면이 열린다.
- 오버레이의 포기·방 이동, 팝업의 같은 기능, 탭 직접 닫기가 중복 요청 없이 안전하게 처리된다.
- 네트워크 실패와 Service Worker 재시작에서도 미전송 이동 기록을 잃지 않는다.

## 5. 랜덤 경로 추첨 UI를 방장에게만 노출

### 목표

서버 권한 검사는 유지하면서, 확장 팝업에서도 방장·대기 상태일 때만 랜덤 경로 추첨 UI를 보인다.

### 구현 단계

1. 팝업 갱신 시 `activeRoomId`의 스냅샷을 조회해 현재 플레이어와 `hostPlayerId`, 방 상태를 비교한다.
2. 현재 사용자가 방장이 아니거나 방이 `waiting`이 아니면 추첨 영역을 숨긴다. 로딩·조회 실패 시에도
   노출하지 않는다.
3. 방장은 현재의 난이도 선택, 10회 상한, 오류 안내를 그대로 사용한다. 서버의 방장 identity 검사와
   상한 검사는 UI와 별개로 유지한다.
4. 방장 변경 기능이 생기기 전까지, 방장이 나간 경우에는 기존 서버 정책대로 방장이 나갈 수 없음을
   안내한다.

### 완료 기준

- 일반 참가자는 팝업에서 추첨 UI와 관련 동작을 볼 수 없다.
- 방장은 대기 상태에서만 UI를 보고, 경기 중·종료 상태에서는 보지 않는다.
- 개발자 도구로 UI를 노출해도 서버는 비방장의 생성 요청을 거부한다.

## 권장 구현 순서

1. 2번과 5번을 먼저 처리하고 단위/Chrome 회귀를 추가한다.
2. 1번을 처리해 오버레이 상태 모델과 확장 메시지 구조를 정리한다.
3. 4번의 탭 수명주기를 구현한다. 이 단계에서는 수동 페어링을 유지한다.
4. 3번을 별도 마이그레이션과 보안 리뷰가 있는 기능으로 구현한 뒤, 수동 페어링 UI를 제거한다.
